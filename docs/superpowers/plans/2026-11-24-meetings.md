# Wren Meetings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Meetings page to Wren (Windows + macOS) that records a Teams meeting as two streams, shows a live named transcript, keeps the user's own notes, and generates Short/Medium/Long enhanced notes with Claude.

**Architecture:** A new Rust module tree `src-tauri/src/meetings/` owns capture → segmenting → transcription (the existing sidecar via `Engine::transcribe`, at most one meeting request in flight) → Teams speaker/mute attribution → SQLite → Tauri events. Enhanced notes are a streamed raw-HTTPS call to the Anthropic Messages API from Rust; the key lives in the OS credential store. React gets a new `meetings` page (list + meeting view with My notes / Transcript / Enhanced tabs) and a Settings section.

**Tech Stack:** Rust (Tauri 2, cpal, rubato, hound, rusqlite, reqwest, `windows` 0.61, objc2), Python sidecar (unchanged API), React 19 + TypeScript, TipTap for My notes, `keyring` crate.

**Spec:** `docs/superpowers/specs/2026-11-24-meetings-design.md` (approved 2026-11-24). Read it before any task.

## Global Constraints

- Branch `feat/meetings` off `main`. **Never push to `main` before Task 15** (a push to `main` auto-releases).
- Teams desktop only. Manual start only. No auto-detect, no consent notice, no floating meeting window.
- One sidecar, one model per OS. No new Python dependencies. Meeting requests reuse `Engine::transcribe`.
- At most **one** meeting transcribe request in flight (dictation waits behind ≤ 1 segment).
- Meeting audio (`me.wav`, `them.wav`, temp segment WAVs) deleted **24 h after the meeting ends**; transcript, my notes and enhanced notes kept until the meeting is deleted.
- Claude: `POST https://api.anthropic.com/v1/messages`, headers `x-api-key`, `anthropic-version: 2026-10-21`, `anthropic-beta: server-side-fallback-2026-07-01`; body `model` (`claude-opus-5-5` default, `claude-sonnet-5-5` option), `stream: true`, `max_tokens: 16000`, `output_config: {effort: "medium"}`, `fallbacks: "default"`; no `thinking`, `temperature`, `top_p`, `top_k` fields. Prices for the cost estimate: Opus 5.5 $4 in / $20 out / $0.40 cache-write-5m≈1.25×in / $0.20 cache read per MTok; Sonnet 5.5 $2 / $10 / 1.25×in / $0.10.
- The API key is stored only in the OS credential store (service `Wren`, account `anthropic-api-key`). Never in settings.json, the DB, logs, events, or any command's return value.
- Text from meetings is never logged (follow the existing "logs counts only, never text" rule).
- UI copy is British English. Name shown for Me lines comes from setting `meetingName` (default `"Maximilian"`). Never hard-code another name for the user.
- New UI uses the existing tokens/components (`src/styles/*.css`, `Tabs`, `Button`, `Banner`, `Empty`, `Toast`) and must look right in Light and Dark at 1200×800 and 960×640 with 0 px horizontal overflow (existing `scripts/check-pages.mjs` sweep).
- Windows: `cargo test --manifest-path src-tauri/Cargo.toml --lib` stays green; macOS work is built and tested on "Lord's MacBook Pro" (T3 environment `8dfac4df-75fb-4822-b848-6862dc31548a`, repo `/Users/maximilian/Code/Wren`) via a delegated thread.
- Commit at the end of every task; update `docs/HANDOFF.md` status section at the end of every task.

## Review Focus

1. **Dictation during a meeting** — holding the hotkey mid-meeting must still paste within today's latency (+≤1 segment) and its words must not appear as a Me line. Test in Task 7 (gate) and Task 13 (live latency).
2. **Teams quits or restarts mid-meeting** (Teams update, crash, leaving and rejoining) — capture must reattach to the new Teams process within ~5 s, not go silent forever. Test in Task 5 (Windows reattach) and the Mac thread in Task 6.
3. **Wren quits/crashes mid-meeting** — on next launch the meeting is `interrupted`, its segments intact, its WAVs finalised (valid headers) or cleanly discarded, and notes can be generated. Test in Task 1 (recovery) and Task 7 (WAV finalise on drop).
4. **Long meeting (2 h+)** — segment queue, WAV size (>2 GB guard: hound's 4 GB limit is fine at 16 kHz mono 16-bit ≈ 115 MB/h), transcript rendering of 2,000+ lines, prompt size. Tests in Task 7 (queue backlog → "Catching up") and Task 11 (virtualised/windowed list or paged render keeps scroll smooth with a 2,500-line fixture).
5. **Bad or missing API key / offline mid-stream** — partial streamed text must not be saved as a finished note; the tab shows the error with Retry; transcript untouched. Test in Task 9 (SSE error mid-stream) and Task 10 (no partial persisted).
